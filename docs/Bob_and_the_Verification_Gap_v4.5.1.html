Capability assessment

Bob and the Verification Gap

IBM Bob moves engineering work faster. IBM cites research showing that speed relocated the bottleneck to review and validation. This is an assessment of what fills it.

Prepared 10 September 2026 Subject: IBM Bob (GA April 2026) · maintainability-agent 3.1.0

Executive summary

IBM Bob is an agentic development environment that plans, writes and modernises code, with claimed delivery gains of 20–40% faster and 50–80% less effort. Those gains are real and they create a second problem, which IBM states in the same announcement.

85% of DevSecOps professionals surveyed agree that AI has shifted the bottleneck from writing code to reviewing and validating it. GitLab 2026 AI Accountability Report, cited by IBM Newsroom, 9 July 2026

Bob ships gates for that shift, and they are process gates: approval checkpoints, policy enforcement, sensitive-data scanning, red-teaming, an ambiguity check on specifications. They govern how work proceeds. None of them measures the condition of the artifact that comes out.

maintainability-agent (MA) is a deterministic product gate. Same tree in, same number out, every time — which is the property that lets a build fail on it. It scores against a reference corpus of 180 repositories across 13 languages, withholds a grade when the evidence cannot support one, and states what examined every value. It is a local process, not a service.

The two do not overlap. Bob produces; MA verifies what was produced. And the integration path exists today: Bob supports MCP, and MA ships an MCP server.

What Bob does, from its own documentation

Stated fairly, because the argument is weaker if it is unfair. Bob is a substantial platform and is ahead of MA on every axis below.

  • Agentic execution — three modes (Agent, Ask, Plan), multi-agent orchestration, subagents with context isolation and user approval before spawning.
  • Enterprise language depth — Java, Python, Node.js, Linux, AIX, Z, and for IBM i: RPG, COBOL, DDS, SQL, CL. Very few tools go there.
  • Modernisation workflows — pre-built and specialised, aimed at decades-old estates.
  • Process governance — role-based approvals mapped to SOX, PCI and HIPAA controls; policy enforcement; automated red-teaming.
  • Code review in the IDE — Branch Comparison and Issue Coverage, which "analyse changes and flag potential issues".
  • Cost telemetry — Bobalytics, for consumption and resource allocation.

Six things MA does that an agentic reviewer cannot

Not "does better" — cannot, as a property of what a language model is.

01 · Determinism

The same answer twice

Same tree, same config, same pinned analyser versions → the same evidence, findings and score. An LLM reviewer is not reproducible, so it can advise but it cannot be the thing that fails a build.

Promise P1, held by test
02 · Calibration

A number with a population behind it

The scale is fitted to 180 mature repositories pinned to exact commits across 13 languages. The constants are re-derivable offline from checked-in inputs, so nobody takes them on faith.

2,749,575 declarations measured
03 · Refusal

It declines to grade

When the evidence cannot support a grade, none is issued — never a dash, never a zero, both of which read as a result. A shallow clone of a real project drops the grade entirely and says why.

ADR 005 · "insufficient" is a real answer
04 · Attribution

Every value names its source

Which analysers ran, which were not applicable, which concepts nothing measured. Silence is reported as silence. A clean section with nothing behind it is the defect this design exists to prevent.

Promise P8
05 · Falsifiability

Every fix carries a test that fails without it

A gate proves each newly cited test fails at the base commit. A fix whose proof passes before the fix is not a proof, and the build says so.

22 of 22 proven, current branch
06 · Two axes, never merged

Clean code with nothing holding it there

Practice level (is anything enforced?) and condition (what did the scanners find?) are reported side by side and never averaged. Their combination is the finding — a clean scan with no enforcement is unverified, not healthy.

ADR 007, structurally enforced

Why a team already running Bob wants this

1. It closes the gap IBM itself named

Bob's 20–40% acceleration lands upstream of review. The survey IBM cites puts 85% of DevSecOps professionals on the other side of that shift. Adding review capacity to match generation capacity is the obvious answer and the wrong one; the affordable answer is a check that runs in seconds and does not get tired. MA audits a 722-file project in 12 seconds and a Go CLI in 2.

2. Different layer, no overlap

Bob's gates ask may this proceed. MA asks what is the condition of what came out. A team can have every approval in place and still ship a module nothing tests; a team can have perfect metrics and no change control. Both are needed and neither substitutes.

3. Cost telemetry is not quality telemetry

Bobalytics answers what the AI consumed. It cannot answer whether the codebase got better. For an engineering organisation reporting on code health, the second question is the one leadership asks and the one that currently has no number attached.

4. It gives AI-written code an objective referee

The uncomfortable question about agentic development — how do we know the volume it produces is any good? — cannot be answered by another agent, because the answer would carry the same non-determinism as the thing under review. It needs an instrument. That is the entire argument in one sentence.

5. The integration already exists

Bob uses external tools through MCP. MA ships an MCP server as its primary surface. A Bob user adds it as a tool and audits from inside the IDE — no pipeline change, no new platform. The CLI is there for the build.

6. COBOL is parsed, and honestly

MA has a COBOL scanner — PROCEDURE DIVISION paragraphs, fixed-form card columns — which matters directly to Bob's IBM i and Z audience. It also reports that COBOL is outside its reference corpus, permanently, with the evidence: GitHub holds one COBOL repository above 500 stars, and what is public is curriculum and Java parsers rather than COBOL codebases. Findings hold; the grade is marked provisional. That disclosure is the product working.

What this assessment does not claim

Absence from documentation is not absence from the product. Every "not documented" cell above means IBM's public materials do not describe the capability. Bob may do these things. If someone in the room knows otherwise, they are right and this table is out of date.

MA is much smaller. It does one thing. It does not generate, modernise, orchestrate, or handle compliance. It has no enterprise support organisation behind it. Against Bob's scope it is an instrument, not a platform — which is the point, but it should not be oversold as anything more.
