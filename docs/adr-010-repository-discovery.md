# ADR 010: Discovery — what is in this tree, and whose code is it

- Status: Accepted
- Date: 2026-08-12
- Scope: What gets scanned, what gets scored, which analyzers are applicable, what the report states about the tree
- Related: [ADR 005](adr-005-insufficient-population.md), [ADR 006](adr-006-analyzer-evidence.md), [ADR 007](adr-007-pillars-and-practice.md)

## Context

Nothing looked at the repository before deciding what to run and what to score. The pool was resolved from the operator's concerns, depth and licence policy; the scan walked whatever `include_extensions` listed; and the score was computed over whatever that produced. At no point did the tool ask *what is actually in this tree*.

Two defects came out of that gap, both measured, both invisible on every repository the tool had previously been tested against.

### Tools claimed coverage of languages that are not present

`kilo` is one C file. complexipy, mypy, pydocstyle, radon, ruff and vulture all ran, produced zero measurements and zero findings between them, and the coverage section reported `documentation`, `style`, `types` and `dead-code` as **examined**. Identical on gson and ripgrep.

The rule that produced this is correct in general and wrong here: *a tool that ran and found nothing has examined its concern.* That is what stops "vulture found no dead code" collapsing into "nobody looked". It holds only when the tool **had input**. A Python linter on a C repository examined nothing, and recording it as coverage is absence-as-value arriving in the section written to prevent absence-as-value.

### Other people's code was scored as the team's own

Adding `.mjs`/`.cjs` to the include list — a correct fix for genuinely unread source — pulled 10,759 files from `packages/mui-icons-material/lib/` into the calibration corpus. Six-line SVG icon wrappers, one per icon, written by `builder.mjs` in the same package. They dropped material-ui's duplication from 3.729 to 2.321 and moved `CALIBRATION_C` from 2.6279 to 2.6414.

The same class elsewhere: 5,090 of whisper.cpp's findings sit in `ggml/`, a library synced from another repository. 16,719 of lapack's sit in `TESTING/`, which `is_test_path` missed because it matched `test` and `tests` but not `testing`. transformers' duplication read 25.567 with its generated modular files included and 13.690 without.

**The existing defence was a list of directory names** — `vendor/`, `third_party/`, `node_modules/`, `migrations/`. `ggml/` was not on it, so a vendored tree counted as first-party because of what its authors happened to call it. Extending the list is not a fix; it is the same mechanism with one more entry, waiting for the next project to choose a different word.

## Decision

**A discovery pass runs before anything else, and classifies every file by language and provenance from evidence the repository itself provides.**

### 1. Classification is by evidence, never by name

Each rule points at something checkable, and the evidence is recorded beside the verdict so a reader can disagree with it:

| Provenance | Evidence |
|---|---|
| `generated` | a generation banner in the file's head; a filename shape no human writes (`*.pb.go`, `*_pb2.py`, `*.designer.cs`); a directory a `package.json` script deletes and rebuilds (`rimraf lib && …`) |
| `vendored` | a `.gitmodules` entry; a script named for the directory it overwrites from upstream (`scripts/sync-ggml.sh` maintaining `ggml/`) |
| `test` | conventional path and name shapes, now including `TESTING/` |
| `first-party` | everything else |

`test_every_classification_carries_the_evidence_for_it` refuses a classification with no evidence. A verdict nobody can check is a guess with better manners.

### 2. Where there is no evidence, the answer is first-party

This module removes code from someone's audit. A false positive silently deletes their own work from their own report, which is the worse direction of error, so the bias is deliberately toward leaving code in.

That bias was tested immediately and in the right direction. The first banner rule matched substrings, and classified material-ui's hand-written `formatMuiErrorMessage.ts` as generated because its docstring says *"It's imported by the code generated by `@mui/babel-plugin`"*. Prose **about** generated code, mid-sentence. Two further iterations were needed: requiring the phrase to open a line rejected curl's genuine `/*** Sample code generated by the curl command line tool ***`, which does not. The rule that holds is **position, not presence** — a declaration comes before the prose, so nothing that reads like a finished sentence may precede it, on its line or the one above.

### 3. A tool with no input is `not-applicable`, not `ran`

A tool whose catalog languages do not intersect the tree records `not-applicable` with a reason naming both halves — *"reads python; this tree is C, so it had nothing to examine"* — and claims no concern coverage.

Any overlap is enough. lizard reads a dozen languages and must not be excluded from a C repository for the absence of Kotlin. Suppressing a tool removes real evidence, so an inapplicable verdict has to be positively supported by a language list sharing nothing with the tree.

The two vocabularies are mapped explicitly. The inventory says `C++` and `C#`; the catalog says `cpp` and `csharp`. Comparing them directly finds no overlap and marks every C++ tool inapplicable — the same defect as concerns against concepts, and the third instance of it in this codebase. `CATALOG_LANGUAGE` is held complete against `KNOWN_SOURCE_SUFFIXES` by a test.

### 4. Generated and vendored code leaves the scored population

It is counted and reported, never silently dropped: `summary.generated_files`, `summary.vendored_files` and `summary.classifications` state what was set aside and why. Excluding code without saying so would replace one dishonesty with another.

### 5. The corpus is re-derived only after this lands

Recorded because the sequencing is load-bearing. Widening what the tool reads widens what contaminates it, in the same act. Any constant fitted before provenance detection embeds material-ui's icon build in the scale.

## Options considered

**A. Extend the exclusion list.** Add `ggml/`, `TESTING/`, `lib/`. Rejected: `lib/` is an ordinary source directory in most repositories, and the approach has already failed once for exactly the reason it will fail again — it can only know the names it was told.

**B. Detect generated code by structure** — a directory of many tiny mutually-near-identical files. Would have caught material-ui's icons. Rejected: it is a heuristic over shape rather than a fact the repository states, and it would misclassify legitimate repetitive code. This project's whole method is evidence over inference.

**C. Ask the operator to configure it.** Rejected as the *only* mechanism — a tool that requires per-repository setup before its score means anything is a tool nobody runs on a repository they did not write. Configuration remains available and overrides discovery.

**D. Score everything and report provenance alongside.** Rejected: it leaves the number wrong and asks the reader to correct it mentally. The score is the artifact people quote.

## Consequences

- Scores move on any repository containing generated or vendored code, and move *correctly*. This is a public change and rides with the schema bump.
- `CALIBRATION_C` was re-derived after this landed and **kept at 2.6279**: a 2,000-resample bootstrap puts the 95% interval at [2.2522, 3.4718], both candidates roll the corpus median to exactly 4.0000, and they differ on one repository in forty by 0.1. See `tools/calibration/sampling_error.py`.
- Coverage shrinks honestly on non-Python repositories. gson, cobra, ripgrep and curl went from reporting 9 of 11 analyzers contributing to 3 of 11, because the other six had nothing to read.
- Detection is partial and will stay partial. Ecosystems this does not yet recognise report their code as first-party, which is the safe direction. New rules are added when a real repository demonstrates the need, not speculatively.
- One more pass over the tree per audit. Measured at under a second on babel's 17,818 files.

## Invariants

1. Every non-first-party classification carries the evidence that produced it.
2. A file with no evidence against it is first-party. Doubt leaves code in the audit.
3. A tool whose languages do not appear in the tree records `not-applicable` and claims no coverage; any overlap makes it applicable.
4. Generated and vendored files are excluded from the scored population **and counted in the report**.
5. Classification reads the repository's own declarations. No rule may be a bare list of directory names.
